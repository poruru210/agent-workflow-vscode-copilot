Agent Workflow
動きだけを理解する

「Copilot版ワークフローがどう動くか」だけを可視化します。 正常経路、Orchestratorによる委譲、FAIL時の診断・修正を別々の図として分離し、必要な関係だけを示します。

中央縦 = Normal Success Path 委譲 = phaseから呼び出して同じphaseへ返す FAIL = 主幹から一時離脱して必要gateへ戻る Audit = read-only
重要： OrchestrationとFAIL loopは「主幹と並行する別工程」ではありません。必要な時だけ主幹から呼ばれる補助動作です。

01 / Bootstrap

最初にCompactかNormalかを分ける

短いread-only回答だけは軽量経路。変更・test・audit・delegation・material riskがあればNormalへ。

Compact条件を
すべて満たす？

YES → Compact

  1. 質問と正本を確認
  2. 必要なfreshnessだけ確認
  3. 回答 + 限界

状態変更もdelegationも行わず終了。

NO / 不確実 → Normal

  1. Work Definition
  2. Risk / Plan
  3. Baseline
  4. 作業種別分岐
  5. 実装・監査・検証

03 / Orchestration

委譲は「主幹のphaseから呼び、結果を同じphaseへ返す」

Orchestrationは主幹とは別の時間軸ではありません。親が必要と判断したphase内で、一時的にsubagentを呼ぶ動作です。

主幹進行中のphaseを所有する

04 / Failure & Correction

FAIL時だけ主幹から一時離脱する

FAIL loopは主幹の横で常時走る工程ではありません。任意phaseがFAIL/未証明になった時だけ入り、根因と変更影響を処分して必要な最も早いgateへ戻ります。

例: Partitioned Verification でFAIL
MAIN FLOW
Partitioned Verification — FAIL 証拠を保存し、その場で次のassertionや症状行へpatchしない
1. Evidence保存input / state / log / identity / environment
2. RC / VER / TEST-RCfirst fault / 責任層 / 検出漏れ / 検証系根因を分離
3. Root-cause Challenge必要ならblind-first read-only独立導出
4. INT / Correction症状ではなく因果link・共有mechanismへ介入
5. New Snapshot / CHG / U1actual deltaと影響差分を再導出
RETURN TO MAIN FLOW
必要な最も早いgateへ戻る 例: New Snapshot → Early Audit → Verification。未変更claimはEvidence Mapで継承。
反復条件： 新しい識別証拠、反証可能な予測、判断を変える合理的見込みがある場合だけ再度回します。同じ証拠しか増えない反復は退出・再計画・限定No-Goへ。

08 / Hooks

Hooksは主幹を進めるものではなく、境界違反を抑える

phase進行の補助ガードです。Hookが動いたこと自体はcorrectness evidenceではありません。

SessionStartdurable stateがあれば再入場contextを追加。
PreToolUseaudit phaseのwriteをdeny。未知terminal操作はask。
SubagentStartstateless invocation境界を明示。
SubagentStopjob runtimeをterminalへ。
PreCompactcontext圧縮前にcheckpoint。
Stopmandatory claimが残る場合、完了誤認を警告。
09 / Evidence

異なる命題を同じ「テストPASS」に潰さない

根因、検出漏れ、介入、変更安全、停止合成、検証モデルを別packetとして保持し、最終的に成果鍵と独立反証鍵を閉じます。
